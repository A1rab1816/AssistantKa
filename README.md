# AssistentKa.ai — Android-проект

Первый рабочий каркас чата на **React Native + Expo SDK 57**. В проект уже включена сгенерированная нативная папка `android/` для открытия в Android Studio.

## Быстрый запуск

1. Установи Node.js из поддерживаемых Expo версий и Android Studio с Android SDK.
2. В корне проекта установи зависимости:

   ```bash
   npm install
   npx expo install --fix
   ```

3. Скопируй шаблон настроек и внеси свой OpenRouter-ключ локально:

   macOS/Linux:

   ```bash
   cp .env.example .env
   ```

   Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

   Открой `.env` и замени значение `OPENROUTER_API_KEY` на свой ключ. **Файл `.env` игнорируется Git.** Настоящий ключ не помещай в `.env.example`.

4. Запусти проект в Android-эмуляторе или на подключённом устройстве:

   ```bash
   npx expo run:android
   ```

   Чтобы открыть нативный Android-проект в Android Studio, сначала выполни эту команду либо `npx expo prebuild -p android`, затем открой папку `android/`.

5. Модель OpenRouter по умолчанию задаётся константой `MODEL_PO_UMOLCHANIYU` в `App.tsx`; поменяй её на модель, доступную твоему ключу.

## Ключ API и GitHub — важно

`.env` не попадёт в обычный коммит благодаря `.gitignore`, но приложение получает ключ при сборке из `app.config.js`. Значение в итоге оказывается внутри клиентского приложения/APK и **не является секретным от пользователей приложения**. Для публичной публикации безопасная схема — сервер-посредник: ключ хранится только на сервере, а приложение обращается к серверу. Не выкладывай APK с личным ключом и лимитами.

Если ключ случайно был закоммичен, удали его из истории репозитория и перевыпусти в OpenRouter.

## Что уже есть в этом первом каркасе

- Новый чат, отправка запроса в OpenRouter и остановка запроса.
- Светлая и тёмная mint-тема, режимы «Размышление» и «Поиск».
- Локальная история, поиск, выбор, переименование и удаление чатов.
- Composer с вложениями, быстрыми действиями, ответами и кнопками копирования/оценки/поделиться.
- Bottom sheet выбора изображения, камеры и файла; экран голосового ввода как UI-заготовка.
- Русские, описательные имена собственных переменных и функций латиницей. Английские поля протокола OpenRouter и имена библиотек оставлены как требует API.

## Что нужно доделать перед полноценным релизом

- Ключ в клиенте нужно заменить серверным посредником для защиты.
- Для фактического распознавания речи нужен модуль speech-to-text.
- На этом этапе выбранный файл отображается как вложение, но байты файла/изображения ещё не отправляются в OpenRouter.
- Ответ выводится целиком после получения; потоковая печать, полноценный Markdown/код/таблицы и источники поиска требуют отдельной реализации и тестирования.
- Перед публикацией протестируй разрешения камеры/файлов, ошибки API, клавиатуру и размеры экранов на эмуляторе и реальном Android-устройстве.
